# M4 演练手册（回滚 / 灰度 / 备份恢复 / 故障注入）

> 所有演练必须记录：开始时间、结束时间、实际耗时、失败点、回填 `docs/m3/03-verification.md`。
> **未演练的项不得在 Go-Live 清单上打勾。**

## 1. 回滚演练（目标 ≤15 分钟）

1. 记录当前版本：`kubectl`/compose 镜像 digest 或 `app_info` 指标；
2. 部署新版本（或模拟坏版本：注入 500/错误配置）；
3. 触发回滚：切回上一镜像 digest（DB 不回滚，迁移均为加法）；
4. 验证：`/readyz` 200、`/healthz` 200、跑 1 条问答 + 1 条办单；
5. 记录耗时；>15min 必须分析（镜像拉取/健康检查/迁移锁）。

## 2. 备份恢复演练（RPO≤15min / RTO≤1h）

1. `powershell -File scripts/backup.ps1 -OutDir D:\backups\e-co`；
2. 新建空库，`restore.ps1 -BackupDir <dir>`；
3. 校验：表数量、`aftersales_biz` 行数、最近一条流转时间；
4. 记录 RTO；确认 binlog 可回放到故障点（RPO）。

## 3. 灰度放量（5% → 20% → 100%）

| 阶段 | 观察窗口 | 通过条件 | 回退动作 |
| --- | --- | --- | --- |
| 5% | 30min | 错误率 ≤0.5%、P95 不劣化 20%、无引用=0 | 比例归零 |
| 20% | 1h | 同上 + 办单成功率 ≥99% | 比例归零 |
| 100% | 24h | SLO 达标、无 P0/P1 | 回滚镜像 |

每阶段记录：请求量、错误率、P95、办单成功率、人工接管率。

## 4. 故障注入

| 故障 | 注入方式 | 期望 |
| --- | --- | --- |
| Redis 挂 | 停 redis | 限流/会话降级放行；缓存失效但不 500 |
| Chroma 挂 | 停 chroma | 检索降级关键词；无结果走兜底 |
| LLM 超时/5xx | 网关 mock 延迟 | `AS-5033` 降级话术；不重试风暴 |
| MySQL 只读/慢 | 加锁/延迟 | `/readyz` 503；写接口快速失败 |
| MQ 挂 | 停 mq | outbox 积压告警；业务仍受理（同事务） |

## 5. 错误预算燃烧

- 快速燃烧（1h，14.4×）：立即停止放量，检查 5xx/延迟/依赖；
- 慢速燃烧（6h，6×）：当天值班排查，评估是否回滚；
- 任何"无引用直出"或"死信"告警：P0，先止血再定位。
